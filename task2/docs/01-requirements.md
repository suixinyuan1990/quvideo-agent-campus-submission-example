# 需求

本文是需求正文，写用户、目标、范围和成功标准。环境、安装、运行和评审入口见 [README.md](../README.md)。

## 用户

使用者是负责内容活动的运营人员。给定活动主题、预算和截止时间后，需要一份能落地的方案，并看到钱花在哪里、是否来得及、方案有没有保存。

评审者用命令重复运行场景，对照 `examples/` 里的输入、输出和 Trace，确认每一步状态和费用与决定一致。

## 目标

在预算和截止时间内得到一份内容活动方案。系统检索合成素材、生成脚本、估算成本，并在检查通过后保存方案。

成功时同时交付：

- 任务计划，覆盖素材检索、脚本生成、成本估算、方案保存
- 各步骤状态和对应的工具结果
- 不超过预算的费用合计
- 不超过截止时间的耗时
- 已保存方案

做不到时交付未完成原因，并保留已经成功的步骤结果。缺预算或截止时间时不补造这两个字段。失败步骤保持 `failed`。未保存时费用合计为 0，缺口单独写在 `gap`。

规划要根据工具的真实返回决定下一步：

- 估算超过预算，或耗时赶不上截止时间：改选仍可执行的方案并再次估算，或停止并给出缺口。
- 工具返回错误：保留失败前的成功结果。失败只阻断当前方案且还有可执行方案时改选；共享的素材检索失败，或没有可执行方案时停止。
- 检索只返回一部分素材：沿用已取到的素材。当前方案缺必要素材时改选能做完的方案，或说明缺什么并停止。
- 同一输入再次执行：识别已保存方案，不重复累计费用。

## 范围

要做的是一次命令行规划、四个工具，以及根据工具返回做的动态决策。合成素材、费用和耗时放在 `data/`。

每次规划至少接收：

| 输入 | 说明 |
| --- | --- |
| 主题 | 内容活动要做什么 |
| 预算 | 允许的费用上限，单位是模拟单位。空值表示缺失，不能当成 0 |
| 截止时间 | 方案必须完成的时间 |
| 合成素材 | 可供检索的活动材料，含是否可用和费用 |
| 工具费用与耗时 | 写在方案目录里。方案估算等于所采用素材费用加脚本费用 |

四个工具固定为素材检索、脚本生成、成本估算、方案保存。费用只来自 `data/plans.json`，调用方和模型都不能临时改价。工具调用不再另加一笔。

入口是 `python -m src.agent`。`acceptance` 写出本地基线。`run` 做单次规划。可选的外部模型使用 OpenAI 兼容接口；三个环境变量都为空时不发起外部调用，验收仍由本地规则完成。

不做网页、账号、真实支付、投放平台和自训模型。不使用 LangChain、LangGraph 或其他 Agent 框架。

失败步骤续跑、部分素材改选、按目录估算择优，以及把状态写到 `data/state/<case_id>.json`，都已实现。续跑是加分项，不替代下面五条必须验收。

## 成功标准

必须同时通过下面五类。同一条实例可以覆盖多个点。至少提交 3 组输入、输出和 Trace，并覆盖正常、信息或资料不足、工具失败。

| 标准 | 怎样算通过 | 实例 |
| --- | --- | --- |
| 正常完成 | 工具成功，费用和耗时都在限制内，方案已保存 | `examples/normal/` |
| 缺预算或截止时间 | 不保存，原因指出缺哪个字段，四个工具为 `not_run` | `examples/missing_info/` |
| 工具失败 | 失败步骤是 `failed`，此前成功的结果还在；有可执行方案时改选，否则停止 | `examples/tool_failure/`、`examples/replan_after_failure/` |
| 预算超限 | 不保存超预算方案。改选预算内方案并再次估算后保存；没有可行方案时返回缺口且不保存 | `examples/over_budget_switch/`、`examples/no_feasible/`、`examples/choose_feasible/` |
| 重复执行 | 第二次识别已保存方案，费用不新增，不丢失第一次的成功结果 | `examples/repeat/` |

参考数字：预算 10 个模拟单位。初始方案估算 12（素材 7 + 脚本 5），替代方案估算 8（素材 4 + 脚本 4）。观察到 12 超过预算后改选替代方案，再次估算得到 8，然后保存。被放弃的 12 不进入费用合计。

两个方案都超过预算时，初始 12、替代 15，最低估算 12，缺口 2，费用合计 0，保存步骤为 `not_run`。

三个方案同时存在时，先按列表顺序估算初始方案 12，再在其余素材都已检索到的方案里改选目录估算最低的一个。高成本方案 15 不执行，低成本方案估算 6 后保存。

另外两条已实现的行为：

- 资料只返回一部分时，保留已取到的素材。缺的资料不能当成已经取全。见 `examples/partial_materials/`。
- 失败后续跑时，已成功步骤不重跑，费用不重算，失败步骤不能改记为成功。同一次进程见 `examples/resume_failed/`。另一次命令读取 `data/state/<case_id>.json`。
