# 方案

## 技术取舍

运行环境是 Python 3.10+ 和标准库。入口是 `python -m src.agent`。数据、输出和 Trace 都是 JSON。测试用 `unittest`。依赖文件 `requirements.txt` 只说明使用标准库，验收不安装第三方包。

没有使用 LangChain、LangGraph 或其他 Agent 框架，因此没有框架版本可记。规划循环、四个工具、依赖选择和 Trace 都在本项目里，方便核对每一次改选或停止。标准库里的 `urllib.request` 负责可选的模型 HTTP 调用，超时 30 秒，协议是 OpenAI 兼容的 Chat Completions，动作用 function calling 的 `propose_action` 返回。

`.env` 中 `MODEL_API_KEY`、`MODEL_BASE_URL`、`MODEL_NAME` 都有值才调用外部模型。验收命令固定走本地规则，避免密钥或模型波动改写基线。模型运行写入 `examples/model_runs/<场景>/`。

费用放在 `data/plans.json`。方案估算等于所采用素材费用加脚本费用，例如 12 = 7 + 5，8 = 4 + 4，6 = 3 + 3。模型不能在动作里改价。被放弃的估算不加入费用合计。未保存时费用合计为 0，缺口写在 `gap`。

耗时用输入里的 `as_of` 到截止日 23:59:59 的整小时数，和方案的 `duration_hours` 比较。参考实例的 `as_of` 是 2026-11-10T09:00:00，截止日 2026-11-20，可用小时数为 254。

## 模块

| 模块 | 职责 |
| --- | --- |
| `src/agent/__main__.py` | `acceptance` 与 `run` |
| `src/agent/orchestrator.py` | 按观察结果取下一步，调用守卫和工具，写回状态 |
| `src/agent/graph.py` | 步骤依赖；失败或超预算后，在检索结果覆盖的方案里选目录估算最低的一个 |
| `src/agent/disk_state.py` | 按 `case_id` 读写 `data/state/<case_id>.json` |
| `src/agent/policy.py` | 无密钥时的规则 R1–R7 |
| `src/agent/model.py` | 把状态发给模型，解析 `propose_action` |
| `src/agent/tools.py` | 素材检索、脚本生成、成本估算、方案保存 |
| `src/agent/guard.py` | 缺字段、超预算保存、失败后继续、非法动作 |
| `src/agent/state.py` | 费用、已保存方案、输出组装 |
| `src/agent/trace.py` | 带序号的事件；`ok: false` 不能写成 success |

`src/agent/planner.py` 只保留原来的导入路径。规则原文在 `data/rules.json`。

依赖是：

1. 素材检索不依赖某一个方案，成功结果供后续方案共用。
2. 脚本生成依赖这次检索，请求里的 `material_ids` 只来自检索结果，并带 `source: material_search`。
3. 成本估算依赖该方案脚本成功，费用只计检索结果里的素材。
4. 方案保存依赖估算同时满足预算和截止时间。

第一个方案仍按列表顺序执行，所以参考实例先看到 12。之后的改选才按目录估算从低到高挑选。

## 调用流程

本地规则的顺序：

1. 缺预算或截止时间则停止，四个工具记为 `not_run`。
2. 同一输入已有保存方案则沿用，步骤记为 `skipped`，本次新增费用为 0。
3. 检索素材。没有方案也没有素材则停止。
4. 方案缺必要素材时，不生成脚本。还有其他方案就改选，否则说明缺什么并停止。
5. 对当前方案生成脚本并估算。估算不超过预算且赶得上截止时间才保存。
6. 超出限制且还有素材都已检索到的方案：记录 `switch`，`reason_code` 为 `budget`，改选其中目录估算最低的一个，再生成脚本并估算。
7. 全部方案都不可行：不保存，缺口等于已经估算过的最低值减预算。
8. 工具返回错误：该步骤记 `failed`。失败只属于当前方案且还有依赖已满足的方案时，保留已成功结果并改选其中目录估算最低的一个，`reason_code` 为 `dependency`。共享的素材检索失败，或没有这样的方案时，停止保存。续跑则把已成功步骤留在状态里。

参考实例 `examples/over_budget_switch/` 的实际顺序是：检索，生成初始脚本，估算得到 12，决定改选，生成替代脚本，估算得到 8，决定保存，然后调用保存。Trace 里的 `decision_source` 是 `local_policy`。

`examples/choose_feasible/` 的实际顺序是：估算初始方案 12，改选低成本方案，估算 6，保存。目录中估算 15 的方案没有调用估算工具。

## 动态决策

本地规则和模型使用同一组动作：`continue`、`switch`、`retry`、`save`、`stop`、`reuse`。

| 规则 | 何时 | 决定 |
| --- | --- | --- |
| R1 | 估算超过预算或赶不上截止时间，且仍有素材都已检索到的方案 | 改选其中目录估算最低的方案，再次估算；通过后再保存 |
| R2 | 全部方案都不可行 | 不保存，返回未完成和费用缺口 |
| R3 | 工具返回错误 | 该步骤记 `failed`。共享步骤失败或没有可改选方案时停止；失败只阻断当前方案时保留成功结果并改选 |
| R4 | 缺少预算或截止时间 | 不补造缺失字段，不保存 |
| R5 | 没有可用素材，或当前方案缺必要素材 | 不把缺失素材当成已取全。能改选就改选，否则停止 |
| R6 | 同一输入已经保存过方案 | 沿用已保存方案，跳过已完成步骤，费用不重复累计 |
| R7 | 当前方案未超过预算且赶得上截止时间 | 直接保存该方案 |

无密钥时，编排器按工具返回直接套用这些规则。Trace 记录改选、保存、停止、沿用和续跑，不在每个工具前再写一条 `continue`。`decision_source` 为 `local_policy`。

有密钥时，`python -m src.agent run --decider model` 把当前预算、最近一次工具结果，以及依赖已满足的剩余方案 id 交给模型。模型只提议动作。守卫先检查：

- 估算尚未成功，或估算超过预算、赶不上截止时间：拒绝 `save`
- 目标方案不在依赖已满足的剩余方案里：拒绝 `switch`
- 当前没有失败步骤：拒绝 `retry`
- 上一步已经 `failed`：拒绝 `continue`
- 动作无法识别，或模型调用失败：停止，不保存，不把这次决策记成成功步骤

方案级工具失败后，若还有依赖已满足的方案，模型循环把改选交回决策器。共享的素材检索失败，或没有可改选方案时停止。本地规则会自己改选；模型循环不代为改选，避免和脚本化动作序列错位。

拒绝时，Trace 同时留下模型提议和守卫的 `reject`。`examples/model_runs/guard_reject_12/` 用脚本化决策器走这条循环：先提议保存估算为 12 的方案，守卫拒绝，再改选并保存估算为 8 的方案。`decision_source` 为 `model`。当前环境没有配置密钥，所以没有在线模型 Trace。

## 状态

步骤状态是 `success`、`failed`、`skipped`、`not_run`。完成运行必须有已保存方案，且费用合计不超过预算。未完成运行的 `saved_plan` 为空，费用合计为 0。

重复执行的键是主题、预算、截止时间和 `plan_set`。同一次进程里的续跑使用内存中的未完成快照：第二次跳过已经成功的工具，只重试失败步骤。

`python -m src.agent run` 在本地规则下还会把状态写到 `data/state/<case_id>.json`，供下一次命令沿用或续跑。文件名用 `case_id`，因为 `over_budget_switch` 和 `repeat` 的主题、预算、截止时间和 `plan_set` 相同。`acceptance` 不读写这些文件。模型运行也不写入。运行时 JSON 已写入 `.gitignore`，不作为基线。
