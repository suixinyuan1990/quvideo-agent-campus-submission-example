# 需求

本文是当前有效需求。运行方式见 [README.md](../README.md)，实现见 [02-solution.md](02-solution.md)。

## 1. 用户

用户是需要查制度或产品说明的内部员工。用户不负责判断哪份文档有效。Agent 负责把依据摊开：哪份文档写了什么、版本日期是哪一天、原文有没有冲突、还缺什么。

要覆盖的问题：

- 制度：适用对象、流程、时限、例外、生效范围
- 产品：功能说明、使用条件、限制、版本差异
- 追问：沿用上一轮的对象、范围或限定条件

不覆盖：起草新制度、审批决策、法律意见、闲聊，以及资料未记载的公司事实。

## 2. 目标

员工询问制度或产品问题时，Agent 只依据给定资料作答，并同时交付：

- 面向员工的回答
- 引用的文档 ID、版本日期与原文片段
- 当前资料还缺什么
- 本轮任务状态

可靠的含义是：结论能回溯到原文。资料不足、互相冲突或工具失败时如实说明，不补写资料里没有的事实。

参考规则：D01 写明报销期限 30 天，D02 写明 15 天，两份都没有适用范围和优先级。问「报销期限多久」时，列出冲突和两边引用，并请求确认适用哪份制度，不能回答 15 天。只检索到 D01、且没有第二份冲突文档时，按 D01 回答。

## 3. 范围

第一版包含：

- 单轮问题，以及带对话历史的追问。
- 两类工具：文档检索、片段读取。
- 根据已有证据决定补充检索、读取原文、追问或停止。
- 命令行跑一次问答，并把 Trace 写到 `examples/`。
- 六类验收场景，以及 FaithEval inconsistent 上的冲突题和只检索到 D01 的题。

第一版不包含：

- 真实企业文档、权限系统、审批流、办公软件和网页界面。
- 员工上传临时文件。
- 用模型自身知识补写资料里没有的制度或产品事实。
- 向量数据库、多租户和在线增量更新语料。
- 把 FaithEval 段落改写成报销制度。
- 剧本模型验收所需的环境变量。真实模型密钥只放在本地 `.env`。

## 4. 输入

| 字段 | 要求 |
| --- | --- |
| 当前问题 | 必填。可以含糊、口语化，或是对上一句的追问。 |
| 对话历史 | 可选。按时间顺序的既往问答，用于消解指代和继承限定。没有历史时按单轮问题处理。 |

可引用的事实只来自预先提供的知识材料，以及本轮工具实际返回的内容。

## 5. 知识材料

验收材料是合成的 FAQ、制度，或 FaithEval 段落，不代表真实公司制度。每份文档至少包含：

| 字段 | 要求 |
| --- | --- |
| 文档 ID | 稳定、唯一，回答时原样引用。 |
| 版本日期 | 用于识别新旧。不能单独替代原文结论。没有日期时保持为空。 |
| 文档类型 | `faq`、`policy` 或 `passage`。 |
| 正文 | 可被检索，并可按片段读取原文。 |
| 适用范围 / 优先级 | 可空。空表示文档没有给出。正文里的「只适用于」「不适用」同样有效。 |

文档之间允许重复、互补或矛盾。有前提的规定不能说成普遍规定。

制度验收语料在 `data/policies/`。FaithEval 在 `data/faitheval-inconsistent/`。同一次检索不混用两个语料。

## 6. 工具

工具返回的文本是唯一可引用的原文。

**文档检索。** 按当前问题，以及从对话历史还原出的对象和限定，检索候选文档。返回文档 ID、版本日期、文档类型、相关片段，以及片段是否完整。检索结果只表示可能相关，不是已经核实的答案。

**片段读取。** 按文档 ID 读取更完整的原文，用于核对摘要、补全被截断的句子、确认适用范围和例外。返回值带文档 ID 和版本日期。原文片段必须是该工具返回的连续原文。

使用边界：

- 先检索，再按需要读取原文。
- 证据被截断、只覆盖问题的一部分，或两份文档可能冲突时，读取原文后再下结论。
- 工具失败不是「库里没有这份资料」。

## 7. 动态决策

模型根据本轮已获得的证据决定下一步，而不是固定走完所有工具。

| 动作 | 何时使用 |
| --- | --- |
| 补充检索 | 当前结果偏题、过窄，或对话限定还没进入检索条件。 |
| 读取原文 | 摘要不够支持结论，片段不完整，或需要核对版本、范围与例外。 |
| 追问 | 缺少作答所必需的对象或范围，继续回答会产生不同结论。追问要指出缺的是哪一个条件。 |
| 停止 | 证据已经足够，或继续调用工具也不会改变结论。 |

停止条件：

- 有一致的原文，且覆盖问题所问的事实。
- 相关文档互相冲突，原文没有效力规则。
- 检索与读取都表明资料没有所问事实。
- 必须先澄清，否则会把不同制度说成同一个答案。
- 工具失败，重试后仍无法取得作答所需的证据。

同一轮可以多次检索和读取。证据已经足够时不再继续调用工具。

## 8. 交付

每一轮返回回答、引用、资料缺口、任务状态。Trace 单独保存，不混进员工可见结果。

**回答**先给结论，再给适用条件和例外。多个要点各自有依据。资料没有写到的部分明确说未记载。

**引用**包含文档 ID、版本日期、原文片段。原文片段必须能在对应工具结果中逐字找到。推断、对比和冲突说明不写进原文片段。

**资料缺口**只列仍会改变结论的缺失项：问题所问但没有材料覆盖的事实、冲突双方都没有写明的效力规则、工具失败导致未能读取的文档。没有缺口时为空。

**任务状态**每轮恰好一个：

| 状态 | 何时使用 |
| --- | --- |
| `answered` | 资料一致，且覆盖了问题所问的事实。 |
| `conflict` | 相关资料对同一要点给出不同结论，原文不能裁决。 |
| `insufficient_evidence` | 没有相关材料，或材料没有写出所问事实。 |
| `needs_clarification` | 缺少必要限定，继续回答会产生不同结论。 |
| `tool_failure` | 检索或读取失败，本轮不能完成核实。 |

部分要点已有证据、另一部分因工具失败无法核实的，状态用 `tool_failure`。已核实的要点仍写入回答和引用。

## 9. 回答规则

**有明确依据。** 相关文档一致，且原文覆盖所问事实时，给出明确答案，附文档 ID、版本日期和原文片段。状态为 `answered`，缺口为空。

**文档冲突。** 两份及以上文档对同一要点给出不能同时成立的结论，且没有适用范围或效力优先级时：

- 并列写出每一方的文档 ID、版本日期和冲突句。
- 不选其中一个作为唯一答案，并请求确认适用哪一份文档。
- 版本日期只说明哪一版更晚，不能单独作为采用依据。
- 状态为 `conflict`。缺口写明缺少效力规则。

两份原文给出同一规定时，按该规定作答，状态为 `answered`，不判冲突。

**资料未覆盖。** 检索没有候选，或候选原文没有所问事实时，说明现有资料不能回答该问题。不使用模型自身知识填补。状态为 `insufficient_evidence`，引用为空，缺口写明缺少的资料类型。

正文写明「只适用于」某一对象，或写明某对象「不适用」时，不能用这份文档回答其他对象。

**相似改写。** 同一事实换一种问法，应得到同一文档 ID、同一版本日期和同一事实结论。回答措辞可以不同。

**上下文追问。** 先把指代和上一轮限定还原成完整问题，再检索。上一轮问某项假期制度、下一轮问「那试用期呢」时，检索对象仍是该假期制度在试用期的规定。历史与当前问题冲突时，以当前问题为准。

**工具失败。** 不把失败解释成没有相关制度。报告哪一个工具失败，以及哪部分未能核实。已经成功读到的证据可以引用。状态为 `tool_failure`。

## 10. 成功标准

六类场景全部通过，才算满足本需求。

| 场景 | 通过标准 |
| --- | --- |
| 明确答案 | 结论与原文一致；引用含文档 ID、版本日期和可逐字核对的片段；状态 `answered`；缺口为空。 |
| 文档冲突 | 同时引用双方原文；指出冲突句子；不宣布唯一答案；版本日期只说明孰新孰旧；状态 `conflict`；缺口写明缺少效力规则。 |
| 资料外问题 | 明确不能从现有资料回答；不编造；引用为空；状态 `insufficient_evidence`。原文没有所问事实时同样拒绝，包括适用范围对不上的文档。 |
| 改写后的相似问题 | 文档 ID、版本日期和事实结论与原问一致。 |
| 上下文追问 | 继承上一轮对象和限定；引用对应该限定下的原文。 |
| 工具失败 | 区分核实失败和资料不存在；状态 `tool_failure`；已取得的证据仍附引用。 |

另外两条替换检查：

- 文档正文改变后，答案跟着改变。删掉唯一适用条款后，改为拒绝回答。
- 两份冲突文档改成同一规定后，不再判冲突。

验收同时检查决策：证据充分时不再无意义地连续调用工具；摘要不完整或出现冲突时先读取原文。

FaithEval 额外条件：

- 冲突题同时引用该题的 D01 和 D02，两个互斥答案都不能单独成为结论，并请求确认适用文档。
- 只检索到 D01 时按 D01 作答，只引用 D01。
- 答案字符串对不齐正文时，引用仍摘自正文，不把对不齐的字符串写成原文片段。
