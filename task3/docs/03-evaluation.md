# 评测

需求见 [01-requirements.md](01-requirements.md)。测量命令是 `python -m pytest`。审计原始记录在 `examples/audit/report.json`，叙述版在 [TEST.md](../TEST.md)。FaithEval 抽样在 `examples/faitheval-sample/summary.json`。

最近一次实测：Python 3.12.8，pytest 9.2.0，`tests/` 共 10 项，10 通过，0 失败，用时 0.67 秒。审计得分 100/100，关键缺陷 0。FaithEval 种子 `20260310`，冲突题 20、单文档题 20，40/40 通过。

## 1. 预期

| 场景 | 预期 |
| --- | --- |
| 明确答案 | `answered`，结论与原文一致，引用可逐字核对，缺口为空。 |
| 文档冲突 | `conflict`，两边都引用，不选边，缺口写明缺少效力规则。 |
| 资料外问题 | `insufficient_evidence`，引用为空。原文没有所问事实、或适用范围不符时同样拒绝。 |
| 相似改写 | 与原问同一文档、同一版本日期、同一事实。 |
| 上下文追问 | 继承上一轮对象，引用对应限定下的原文。 |
| 工具失败 | `tool_failure`，并说明不是资料库里没有内容。 |
| 替换正文 | 答案跟着正文变。删掉唯一适用条款后拒绝。两份改成同一规定后不再判冲突。 |
| FaithEval | 封闭池内，冲突题不选边，单文档题按 D01 作答。 |

高分依据是检索改进和冲突处理。无依据回答或引用不能支持结论，记为关键缺陷。

## 2. 实际结果

制度语料上的结果：

| 场景 | 状态 | 实际结论 | 动作 |
| --- | --- | --- | --- |
| 明确答案 | `answered` | `POL-LEAVE-001`：10 天带薪年假 | `search` → `finish` |
| 相似改写 | `answered` | 同一文档、同一句 10 天 | `search` → `finish` |
| 文档冲突 | `conflict` | D01 为 30 天，D02 为 15 天，请确认适用文档。D02 较晚，日期不能单独作为依据 | `search` → `read` → `read` → `finish` |
| 资料外问题 | `insufficient_evidence` | 现有资料不能回答该问题。引用为空 | `search` → `finish` |
| 原文没有所问事实 | `insufficient_evidence` | 发票、年假结转、预约会议室、试用期工资四题都拒绝，引用为空 | `search` → `finish` |
| 上下文追问 | `answered` | `POL-LEAVE-PROB`：每满一个月 0.5 天 | `search` → `read` → `read` → `finish` |
| 工具失败 | `tool_failure` | 片段读取失败，并写明不是资料库中没有相关内容 | `search` → `read` → `read` |
| 编造引用 | `insufficient_evidence` | 错误引用被退回一次，第二次仍不合法时改为证据不足 | 由测试模型驱动 |

替换文档只发生在内存中，不改 `data/policies/documents.jsonl`：

| 替换 | 实际结果 |
| --- | --- |
| 10 天改为 12 天 | 答案改为 12 天。动作仍是 `search` → `finish`，因为仍然只命中这一份完整文档。 |
| 删掉满一年条款，改成食堂菜单 | 拒绝回答。不再用「只适用于试用期」的制度回答满一年员工。 |

## 3. 曾经失败、现已改过的行为

这些是同一套标准下测到的失败，当前代码已不再出现：

1. 检索有关键词重叠就作答。问发票、结转、预约会议室、试用期工资时，会拿相关但没有该事实的句子回答。
2. 删掉满一年条款后，用写明「只适用于试用期员工」的原文回答满一年员工。
3. 两份报销制度改成相同的 20 天后，两边引用都是 20 天，状态仍是 `conflict`。
4. 句子切分把「0.5」切成「0.」，试用期追问的结论丢失小数。
5. FaithEval 初测 25/40。近义阈值过高时，改写幅度大的冲突对被收成单文档答案；单文档引用如果只取最相似的一句，又会漏掉答案所在的后文。
6. 为了修第 3 条，一度把「最相似的两句相同」当成没有冲突。一对全文并不相同、但开头句子相同的 FaithEval 文档因此被答成单方结论。抽样从 40 掉到 39。改为只在全文相同（忽略空白和标点）时取消冲突后，恢复 40/40。

第 1 次审计因此是 75 分、不合格，关键缺陷 2 条。修复后重测为上面的 100 分。

## 4. 限制

- 短语路对「报销期限多久？」没有贡献。问句里没有数字、金额或 4 到 8 字的连续制度用语时，这一路是空的，实际靠 BM25 和字符 3-gram。
- 单文档引用保留该次读取的整段正文，回答本身用最贴问题的句子。这样答案所在的后文仍在引用里。引用还没有收成单独那一句。
- 英文问句不做「所问事实必须出现在原文」的拒绝。FaithEval 题面有错字，严格按字面拒绝会把本来有原文支持的题判成证据不足。中文问句会做这层检查。
- 守卫核对引用是连续原文、版本日期和状态是否匹配。它不重新检查「问句里的事实是否在引用中」。剧本模型在作答前过滤；真实模型目前靠系统提示，测试没有调用真实接口。
- 剧本模型的下一步里没有主动 `ask`。缺限定时，当前路径是拒绝或列出冲突，而不是向用户追问一个具体条件。`needs_clarification` 只在模型返回 `ask` 时出现。
- FaithEval 评测使用该题自己的封闭文档池，不检验在 3000 份文档里的开放检索能否把 D01 和 D02 一起找回来。
- 207 份 FaithEval 文档的 `supported_answer` 不是正文里的连续字符串。引用仍摘正文。单文档是否通过，取决于预期答案是否出现在回答或引用中。
